# 아키텍처와 신뢰 모델

## 목표

Re-cat의 목표는 “그럴듯한 코드 설명”이 아니라, 호출 관계가 정적 분석 결과에 근거한 코드 인수인계 답변을 제공하는 것입니다.

## 구성 요소

| 구성 요소 | 책임 |
| --- | --- |
| FastAPI | 인증, API/SSE, 관리자 작업 조정, 공통 오류 계약 |
| MCP 서버 | 정적 분석 그래프·문서 절을 읽기 전용 도구로 제공 |
| 분석기 | Python AST, Java tree-sitter로 함수·호출 관계를 추출 |
| LangGraph | 질문 라우팅, 탐색, 설명, 검증, fallback 상태 전이 |
| Ollama | 분류·탐색 선택·설명 생성·문서 임베딩 |
| PostgreSQL + pgvector | 등록부, 대화, 감사 메타데이터, 문서 임베딩 |
| Vue 프록시 | 로컬 사용자·관리자 화면 제공 |

## 코드 질문 흐름

```text
gate → route → locate → explore → explain → verify → finalize
                         ↑                    │
                         └── 재설명 ──────────┘
                                              ↓
                                           fallback
```

1. `gate`는 저장소 민감도와 추적 정책을 결정합니다.
2. `route`는 코드·문서·잡담 경로를 분류합니다.
3. `locate`는 정적 검색으로 시작 함수 후보를 찾습니다.
4. `explore`는 MCP를 통해 허용 깊이와 호출 횟수 안에서 그래프를 탐색합니다.
5. `explain`은 구조와 마스킹된 소스를 근거로 설명 및 호출 주장 목록을 생성합니다.
6. `verify`는 모든 호출 주장을 실제 호출 그래프와 대조합니다.
7. 검증 실패 시 재설명 후에도 통과하지 않으면 설명을 버리고 정적 결과만 반환합니다.

## 문서 질문 흐름

문서는 코드의 진실 원천이 아닙니다. 문서에 적힌 `A → B` 같은 호출 주장은 호출 그래프와 대조해 직접 일치, 간접 일치, 불일치, 코드에 없는 이름, 확인 불가로 표시합니다. 업무 규칙·일정·정책 문장의 사실성은 자동 검증 대상이 아닙니다.

문서 검색은 키워드와 로컬 `bge-m3` 임베딩을 RRF로 결합합니다. 임베딩이 실패하면 키워드 검색으로 명시적으로 낮아집니다.

## 데이터 경계

- 코드와 업로드 문서 원문은 파일 시스템에 둡니다.
- PostgreSQL에는 저장소 등록부, 대화, 감사 메타데이터, 문서 절 해시와 벡터를 저장합니다.
- 감사 로그에는 코드 본문·질문 본문·인증 값이 아닌 메타데이터만 기록합니다.
- 호출 그래프는 프로세스 메모리 LRU 캐시이며 저장소 revision이 바뀌면 무효화합니다.

## 신뢰 경계와 한계

정적 분석으로도 동적 호출을 완전히 알 수 없습니다. Python의 `getattr`·콜백·동적 import, Java의 AOP·프록시·다중 구현체·복잡한 타입 추론은 `unresolved` 또는 `ambiguous`로 남깁니다.

따라서 Re-cat은 다음을 보장하지 않습니다.

- 호출되지 않는 동적 경로의 완전한 발견
- LLM이 서술한 의도·이유의 사실성
- 문서 내 업무 규칙의 사실성
- 다중 워커 또는 다중 서버에서의 분산 동시성

## 확장 방향

현업 다부서 운영 시에는 SSO/OIDC, 역할·부서 기반 저장소 인가, PostgreSQL RLS, 작업 큐, 분산 락, 격리 분석 워커를 추가합니다.
